## 상태별 점검

### 기본 상태

- 페이지 제목은 문서의 목적을 바로 설명합니다.
- 첫 화면의 큰 제목은 시네마틱 디스플레이, 본문은 UI sans 스택을 사용합니다.
- 모티프는 구조를 보조하며 본문 정보를 가리지 않습니다.

### 좁은 화면

- 3열 모티프 카드는 CSS media rule에 따라 1열로 전환됩니다.
- 긴 URL과 코드 토큰은 인라인 문장과 분리해 읽을 수 있습니다.
- 표는 짧은 셀 문장과 명확한 열 제목을 사용합니다.

### 다크 모드

- 문서 셸의 foreground, muted, border, card 토큰이 함께 전환됩니다.
- 골드는 장식·도착점으로만 사용하고 본문 텍스트 대비를 대신하지 않습니다.
- 그림자 대신 2px 구조선과 면 분할로 계층을 표시합니다.

### 접근성

- 제목은 `h1 → h2 → h3` 순서를 지킵니다.
- 표는 헤더 행을 포함하고, 링크 텍스트만 읽어도 목적을 알 수 있게 작성합니다.
- 로고·아이콘은 의미가 있을 때 대체 텍스트를 제공하고, 장식 모티프만으로 상태를 전달하지 않습니다.
- `prefers-reduced-motion` 사용자는 모션 전환 없이 동일한 정보에 접근할 수 있어야 합니다.

## 최종 브라우저 증거

로컬 Chromium headless에서 다음 세 viewport를 settled 상태로 캡처했습니다.

1. Desktop 1440px / light — 제목, 표 정렬, 본문 대비 확인
2. Mobile 390px / light — 표를 `720px` 최소 폭 가로 스크롤 영역으로 유지
3. Desktop 1440px / dark — surface, border, foreground, gold accent 전환 확인

키보드 Tab smoke test에서는 브랜드 링크, 검색 버튼, 사이드바 버튼, 현재 페이지 링크, 목차 링크, 표 region이 순서대로 포커스를 받았고 `outline` 또는 `outline-offset`가 적용되었습니다. 표 region은 `tabIndex={0}`과 `focus-visible` 규칙으로 키보드 사용자가 가로 스크롤 영역을 인지할 수 있습니다.

문제가 발견되면 시각적 임의 보정보다 토큰·레이아웃 소유자를 먼저 수정합니다. 현재 공개 포트폴리오의 MDS-30 release gate는 **PASS**입니다.
